# StockTrade — Fintech-Grade Simulated Trading & DBMS Platform

**StockTrade** is a complete, runnable, college-grade Database Management Systems (DBMS) project simulating a realistic stock trading platform with **virtual money only**. Built strictly according to relational database principles, it demonstrates transaction management, ACID guarantees, pessimistic row-level locking, append-only financial ledgers, stored procedures, triggers, multi-interval OHLC time-series aggregation, and a 5-layer secure AI-to-SQL assistant.

> [!NOTE]
> **SIMULATED MARKET DATA ONLY**: No real money, orders, or payments are processed. All market movements are generated by an Ornstein-Uhlenbeck bounded random walk coordinated across processes via MySQL advisory locks.

## 1. Technology Architecture

| Layer | Technology | Purpose |
|---|---|---|
| **Backend** | Python 3.11+ / Flask 3 | Application factory, modular Blueprints, server-side sessions, CSRF protection, and rate limiting. |
| **Database** | MySQL 8.0 (InnoDB, `utf8mb4`) | Atomic transactions (`READ COMMITTED`), stored procedures (`sp_execute_trade`), immutable triggers, and views. |
| **Data Access** | SQLAlchemy 2.x Core | Parameterized SQL queries, repository pattern, connection pooling. |
| **Frontend** | React 18 / Vite / Chart.js | Modern Single-Page Application (SPA) with live price updates, interactive charts, and one-click demo logins. |
| **Market Engine** | Python In-Memory Walk + SSE | Target 500 ms (2 ticks/sec) stochastic walk with decoupled 1.0s batch MySQL persistence and advisory lock. |
| **SQL Parser** | `sqlglot` (MySQL Dialect) | Abstract Syntax Tree (AST) validation blocking mutations, stacked queries, and unauthorized tables across both AI and Manual SQL modes. |
| **AI Router** | Multi-Provider Failover | Grok &rarr; Google Gemini &rarr; OpenRouter &rarr; Deterministic Local Template Fallback. |
| **Tests** | `pytest`, `pytest-cov` | 94 comprehensive unit, integration, concurrency, and security tests with 100% pass rate. |

## 2. Quickstart on Windows (VS Code)

### Prerequisites
1. **Python 3.11+** installed and available in PATH.
2. **Node.js 18+** installed (Node v24 and npm 11 verified).
3. **MySQL 8.0 Server** running locally on port `3306` (e.g. root password `root`).

### Step 1: Environment Setup
In PowerShell from the project root directory:
```powershell
# Create Python virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install Python dependencies
pip install -r requirements.txt

# Install frontend dependencies
cd frontend
npm install
npm run build
cd ..
```

### Step 2: Initialize Database
Provisions databases (`stocktrade` and `stocktrade_test`), creates dedicated DB users (`stocktrade_app` and `stocktrade_ai_ro`), executes DDL schemas, triggers, stored procedures, seeds 100 Indian equities, demo users, and backfills 7 days of 1-minute historical prices:
```powershell
.\init_db.ps1
```

### Step 3: Run Test Suite
Executes all 94 automated tests across AI AST security, Manual SQL mode validation, RBAC permissions, broker tenant isolation, concurrency, database stored procedures and triggers, market simulation, investor watchlists & alerts, and trading:
```powershell
.\run_tests.ps1
```

### Step 4: Start the Platform
Launches the Flask application and autonomous market simulator:
```powershell
.\start.ps1
```
Open **[http://127.0.0.1:5000](http://127.0.0.1:5000)** in your browser.

## 4. Five-Minute Viva Demonstration Script

Follow this step-by-step walkthrough to present all key DBMS and software engineering concepts during project evaluation:

### Step 1: Authentication & Brute-Force Lockout (1 min)
1. Open `http://127.0.0.1:5000`. Point out the clean fintech UI and one-click demo login buttons.
2. Enter invalid credentials 5 times for `investor_karan`.
3. Show the message: **"Account locked for 15 minutes due to consecutive failed login attempts."**
4. Click the **Admin** button to log in. Navigate to **User Accounts**, locate `investor_karan`, and click **Reset Lockout** to demonstrate administrative access control.

### Step 2: Market Simulator & OHLC Aggregation (1 min)
1. In the top bar, highlight the persistent simulation badge: `SIMULATED MARKET DATA · last update hh:mm:ss`.
2. Navigate to **Market Directory**. Point out real-time green/red cell flashes as prices tick every few seconds.
3. Click the **Chart** button next to `TCS` or `RELIANCE`. Toggle between **1M**, **5M**, and **1H** intervals.
4. *Viva explanation:* Explain that candles are computed dynamically via SQL timestamp bucketing (`GROUP BY UNIX_TIMESTAMP(recorded_at) DIV interval`) over indexed historical prices.

### Step 3: Atomic Trade Execution & Ledger Immutability (1 min)
1. Log in as **Investor Rahul** (`investor_rahul`). Note the ₹1,00,000 opening balance.
2. Click **Trade** on `INFY`. Select **BUY**, enter `5` shares, review the cost breakdown (0.10% investor brokerage, min ₹1.00), and click **Confirm BUY**.
3. Navigate to **Transactions & Ledger**. Show that the trade created:
   - An `Orders` record (`EXECUTED`).
   - A `Holdings` position with weighted average cost.
   - Two `Account_Ledger` entries: `BUY` (-trade value) and `FEE` (-brokerage).
4. *Viva explanation:* Explain `sp_execute_trade` and show how triggers `trg_ledger_block_update` and `trg_ledger_block_delete` prevent any ledger alterations at the database engine level.

### Step 4: Broker Portal & Tenant Isolation (1 min)
1. Log in as **Broker Arun** (`broker_arun`).
2. Navigate to **Client Management**. Point out assigned clients (`investor_rahul`, `investor_sneha`, `investor_vikram`).
3. Click **Onboard New Investor**. Fill in the form to atomically create an investor, opening grant, and assignment in a single transaction.
4. Open **Commission Analytics** to show platform-funded broker commission (40% of collected brokerage).
5. *Viva explanation:* Explain that if Broker Priya attempts to fetch Rahul's profile, the system returns `404 Not Found` (never 403) to prevent tenant resource enumeration.

### Step 5: Safe AI-to-SQL Assistant (1 min)
1. Click **AI SQL Assistant** in the sidebar.
2. Click the quick prompt: *"What are my open stock holdings and their current values?"*.
3. Inspect the response:
   - **AST VALIDATED** badge.
   - Generated SQL restricted to view `v_investor_portfolio`.
   - Results table scoped to `@current_user_id`.
   - Natural language grounded summary.
4. Try typing a malicious mutation: `DROP TABLE Stocks;`. Show that the `sqlglot` AST parser instantly intercepts and blocks the query before it ever reaches the database.
